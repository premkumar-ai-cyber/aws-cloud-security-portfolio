# 🌐 Host a Static Website on Amazon S3

## 📌 Project Overview

This project demonstrates how to host a static website using **Amazon Simple Storage Service (Amazon S3)**. Instead of using a traditional web server, Amazon S3 is configured to store and serve static website files such as HTML, CSS, JavaScript, and images directly over the internet.

During this project, I created an S3 bucket, uploaded the website files, enabled static website hosting, configured public access permissions, resolved access issues, and secured the website using S3 Bucket Policies. This project provided practical experience with AWS storage services, website hosting, access control, and cloud security best practices.

---

# 🎯 Objectives

The primary objectives of this project were to:

- Create an Amazon S3 bucket

- Upload website files

- Configure Bucket Policies

- Host a fully functional static website

# ☁ AWS Services Used

## Amazon S3 (Simple Storage Service)

Amazon S3 is an object storage service provided by AWS that allows users to store and retrieve unlimited amounts of data from anywhere in the world. S3 is highly scalable, durable, secure, and commonly used for:

- Static Website Hosting
- File Storage
- Backups
- Disaster Recovery
- Data Lakes
- Application Assets

---

## AWS IAM (Identity and Access Management)

AWS IAM is used to securely manage access to AWS resources.

Although the website is hosted on Amazon S3, IAM permissions determine who can create buckets, upload objects, modify policies, and manage AWS resources.

# 🚀 Implementation Steps

### Step 1 — Created an Amazon S3 Bucket

- Opened Amazon S3
- Selected Mumbai Region (ap-south-1)
- Created a globally unique bucket
- Enabled ACLs during bucket creation

**Purpose**

The S3 bucket acts as the storage location for all website files.

---

### Step 2 — Uploaded Website Files

Uploaded:

- index.html
- Images
- Website assets

These files collectively form the static website.

---

### Step 3 — Enabled Static Website Hosting

Configured:

- Static Website Hosting
- Index document = index.html

Amazon S3 generated a Website Endpoint URL that allows the website to be accessed over the internet.

---

### Step 4 — Fixed the 403 Forbidden Error

Initially the website displayed

```
403 Forbidden
Access Denied
```

This occurred because the uploaded objects were not publicly accessible.

To resolve the issue:

- Enabled public read permissions
- Updated Object ACLs
- Verified website accessibility

---

### Step 5 — Configured Bucket Policy

Created a Bucket Policy that prevents accidental deletion of the **index.html** file.

This demonstrates how Bucket Policies provide fine-grained access control.

---

### Step 6 — Tested the Policy

Attempted to delete

```
index.html
```

AWS denied the request because the Bucket Policy explicitly blocked deletion.

This confirmed that the security policy was working correctly.

# 🔐 Security Best Practices Implemented

During this project, I followed several AWS security best practices:

- Enabled Static Website Hosting only after uploading files
- Configured Public Read access only for required website objects
- Used Bucket Policies to secure important files
- Protected the main webpage (index.html)
- Understood the difference between ACLs and Bucket Policies
- Applied the Principle of Least Privilege

# 📚 Key Concepts Learned

## Amazon S3 Bucket

A Bucket is a logical container used to store objects inside Amazon S3.

---

## Object

An object is an individual file stored inside an S3 bucket.

Examples:

- HTML files
- Images
- Videos
- CSS
- JavaScript

---

## Static Website Hosting

Static Website Hosting allows Amazon S3 to serve website files directly to users without requiring a web server.

---

## Website Endpoint

A Website Endpoint is the public URL generated by Amazon S3 that allows users to access the hosted website.

---

## Access Control List (ACL)

ACLs are legacy permission mechanisms that grant read or write permissions on buckets or individual objects.

---

## Bucket Policy

A Bucket Policy is a JSON-based resource policy that controls access to an S3 bucket and its objects.

Bucket Policies provide centralized and fine-grained access control.

---

## 403 Forbidden Error

The 403 Forbidden error occurs when users do not have permission to access objects stored inside an S3 bucket.

This was resolved by updating object permissions.
